Introduction

Qu’est-ce qu’un projet ?

Un projet peut être présenté comme un travail organisé, réalisé par une équipe, pour atteindre un objectif défini et produire un ou plusieurs livrables.

Un projet comporte notamment :

  • une équipe : les personnes qui travaillent sur le projet
  • un sujet : ce sur quoi porte le projet
  • des objectifs : ce que l’on cherche à accomplir
  • des données : les informations nécessaires au projet
  • du code : les traitements et analyses réalisés
  • des méthodes : les choix méthodologiques permettant d’atteindre l’objectif
  • des livrables : les productions attendues à la fin du projet
  • un calendrier : les différentes étapes et échéances
  • une organisation : la répartition des tâches et le suivi de leur avancement

Démarrer un projet

Avant de commencer, prenez le temps de faire connaissance avec les membres de votre groupe et de définir votre organisation.

Discutez notamment :

  • des forces et compétences de chacun : programmation, statistiques, rédaction, organisation
  • des appétences de chacun : quelles tâches aimez-vous particulièrement ?
  • de vos éventuelles contraintes d’organisation
  • de vos modes de communication : outils utilisés, fréquence des échanges, réunions
  • de la répartition des rôles et des premières tâches
  • d’une première version macro de votre calendrier

Les rôles ne sont pas nécessairement fixes : ils peuvent évoluer au cours du projet. L’objectif est que chacun participe aux différentes dimensions du projet et que le travail ne repose pas sur une seule personne.

Calendrier et livrables

Un diagramme de Gantt permet de visualiser là où vous en êtes et quelles sont les prochaines échéances. Il est rapide à réaliser et très utile.

Suivre les tâches

Au cours d’un projet, de nombreuses tâches doivent être réalisées. Il est facile d’en oublier certaines ou de ne plus savoir précisément ce qui a été fait, ce qui est en cours et ce qu’il reste à faire.

Une liste de tâches ou un Kanban permet de centraliser le suivi du projet et de donner à toute l’équipe une vision commune de son avancement.

Un Kanban simple peut par exemple comporter les colonnes suivantes :

🚧 Schéma

À faire → En cours → À relire → Terminé

Chaque tâche est représentée par une carte que l’on déplace au fur et à mesure de son avancement.

Cet outil permet notamment de :

  • ne pas oublier les tâches à réaliser ;
  • savoir qui travaille sur quelle tâche ;
  • visualiser rapidement l’avancement du projet ;
  • identifier les tâches bloquées ;
  • répartir le travail au sein du groupe.

Les outils du projet

Un projet statistique mobilise plusieurs outils, chacun répondant à un besoin particulier. Il est important de savoir où réaliser chaque tâche et où stocker chaque ressource.

Besoin Outil
Environnement de travail SSPCloud
Code R ou Python
Versionner et partager le code Git / GitHub
Stocker les données S3
Produire des documents et rapports Quarto
Suivre les tâches GitHub / Kanban

Ces outils sont complémentaires. L’objectif du projet sera de les utiliser ensemble pour construire un travail organisé, collaboratif et reproductible.

2 Créer et organiser son dépôt

Passons maintenant à la gestion de votre code.

2.1 Dépôt distant

Le remote est le dépôt commun à toute l’équipe. Il permet de vous synchroniser.

Votre code sera stocké dans un dépôt GitHub.

    • Repository name : ensai-projet-stat-1a
    • Description: Projet statistique de première année
    • Visibility Level : Private
    • ☑ Cochez Add a README file
    • Add .gitignore : R
    • Choose a license : MIT Licence
    • Cliquez sur Create Repository

Ceci n’est à faire qu’une seule fois.

2.2 Dépot local

Avant de créer votre dépôt local (code sur lequel vous allez travailler), il faut créer votre environnement de travail.

    • Vérifiez que votre Token est présent
    • Renseignez l’url de votre dépôt GitHub

Si tout s’est bien passé, un clone de votre dépôt a été créé dans votre service. Vous voyez apparaitre votre dépôt et ses fichier dans l’explorateur en bas à droite.

NoteSi votre dépôt n’a pas été créé

Dans le terminal de votre service, clonez manuellement en utilisant le token :

  • git clone https://$GIT_PERSONAL_ACCESS_TOKEN@github.com/<username>/<repo_name>.git

Vous allez commencer par vérifier que vous arrivez bien à envoyer du code vers le remote.

Toutes les actions ci-dessous sont à faire dans Rstudio.

2.4 renv

Lorsque plusieurs personnes travaillent sur un même projet, il est important que tout le monde utilise les mêmes packages et les mêmes versions.

renv permet de créer un environnement R isolé et propre au projet et d’enregistrer les packages utilisés ainsi que leurs versions.

Cette commande crée un dossier renv/ et un fichier renv.lock (qui stocke la version de R utilisée, les packages nécessaires et leurs versions).
Ne les supprimez pas !
Le fichier renv.lock doit être versionné dans Git.

Commandes utiles :

  • renv::install("<package>") pour installer un package
  • renv::dependencies() : quels sont les packages utilisés dans le code
  • renv::status() : pour voir les différences entre les packages installés et renv.lock
  • renv::snapshot() : enregistre l’état des packages dans renv.lock
  • renv::restore() : applique renv.lock i.e. désinstalle les packages en trop, installe les packages manquants

Vous allez avoir besoin des packages suivants :

  • dplyr : manipulation de données (pipes, mutate, select…)

  • stringr : manipulation de chaînes de caractères

3 Charger et apurer

3.1 Charger les données brutes

Commençons par charger le fichier.

Dans un dépôt git, il ne faut pas laisser tout trainer à la racine, sinon cela devient rapidement le bazar.

Les fichiers contenant du code sont à placer dans un dossier src (sources).

🚧 Ne pas donner le code, dire de lire la doc usages basiques du datalab (et màj cette page)

import.R
rm(list=ls())

library(aws.s3)

bucket <- "ludo2ne"
filepath <- "projet/input/loto_201911.csv"

loto_raw <- aws.s3::s3read_using(
    FUN = readr::read_delim,
    delim = ";",
    object = filepath,
    bucket = bucket,
    opts = list("region" = "")
)

3.2 Mettre les données au propre

Certaines colonnes ne nous interessent pas, certaines données sont mal formatées. Il faut mettre tout cela au propre avant de commencer les analyses.

A partir du dataframe loto_raw, vous allez créer un nouveau dataframe propre que vous nommerez loto

Vous avez maintenant un jeu de données propre, exportez-le vers S3.

aws.s3::s3write_using(
  x = loto,
  FUN = readr::write_csv,
  object = "projet/output/loto.csv",
  bucket = bucket,
  opts = list("region" = "")
)
